# AI mix surface — спецификация шлюза REAPER Workbench

Документ описывает, каким должен быть MCP-шлюз и библиотека, чтобы агент мог выполнить
всю работу с треком: свести, обработать, автоматизировать, отмастерить и проверить —
имея только состояние проекта, референсы и измерения.

Границы — это **политика, а не отсутствие инструментов**. Шлюз обязан уметь почти всё,
что умеет человек за пультом; что именно делается сейчас, решается запросом и фиксируется
в журнале.

- по умолчанию **аранжировка записанных инструментов не меняется**: нет перестановок,
  удалений и «подклеек» живых дублей без явного указания;
- **MIDI-партии можно писать и править**, если это запрошено (бас, барабаны, клавиши,
  аккордеон): ноты, длина, velocity, канал, квантизация, транспозиция;
- сэмплирование и замена ударов допустимы как обработка, но только по явной команде;
- всё остальное — обработка, уровни, панорама, пространство, динамика, автоматизация,
  мастеринг, выравнивание — в области работы по умолчанию.

## 1. Три принципа

1. **Адресация вместо операций.** Любое свойство проекта читается и пишется по пути.
   Новое свойство не требует нового инструмента.
2. **Цели из референсов.** Допуски и целевые значения приходят из референсных записей
   (пер-метрический выбор, не среднее по больнице), а не из зашитых констант.
3. **Проверка числом.** После каждой записи — рендер участка и дельта к цели или к
   предыдущей версии. Утверждение без замера не делается.

## 2. Слои шлюза

| слой | назначение | статус |
|---|---|---|
| Сессия и адресация | чтение/запись по путям, батчи, ревизии | **новый** (`state`, `apply`) |
| Контекст | один бандл «всё про трек» для загрузки в голову | **новый** (`context`) |
| Цели | референсы → цели по (роль, секция, метрика) | **новый** (`targets`) |
| Проверка | рендер → дельта → вердикт → журнал | **новый** (`verify`, `journal`) |
| Измерения | матрица 100 мс по источникам, маскировка, ширина | есть (`analyze`, `mix_evidence`, `spatial_timeline`, `timeline_context`, `edit_map`) |
| Слух | текст о фрагменте от аудиомодели | есть частично (`spatial_*`, `flamingo_*`) → сводится в `listen` |
| Рендер и доставка | секция/мастер/стем, сравнение версий | **новый** (`render`, `compare`; `save` есть) |
| Обнаружение | каталог API, поиск, произвольный вызов, экшены | есть (`capabilities`, `api_search`, `api_call`, `action`) |

## 3. Полная поверхность инструментов

### 3.1 Универсальное ядро (новое)

```
reaper_state(paths: list[str] | None = None, scope: str = "project",
             expected_revision: dict | None = None) -> dict
    paths=None → индекс дерева: какие объекты есть и по каким адресам.
    paths=[...] → значения с единицами; для параметров FX — normalized, real, display.

reaper_apply(ops: list[{path: str, value: Any}], mode: "preview"|"apply"|"undo",
             expected_revision: dict, plan_id: str | None = None,
             reason: str | None = None) -> dict
    preview → before/after по каждому пути, проект не меняется.
    apply   → одна транзакция под expected_revision, возвращает новую ревизию и plan_id.
    undo    → откат по plan_id при совпадении ревизии.

reaper_context(sections: "auto" | list, refs: list[str] | None = None,
               detail: "map" | "full" = "map") -> dict
    Роли и шины, секции, FX-цепочки, карта измерений «роль × секция», цели, голова журнала.
    Это то, что агент загружает при старте и держит в контексте.

reaper_targets(action: "register"|"build"|"list"|"compare", refs=None, sections=None,
               weights: dict | None = None) -> dict
    register — принять референсы (путь, громкость, разметка секций).
    build    — построить цели по (роль, секция, метрика): значение, источник, допуск, вес.
    compare  — текущее против целей, без правок.

reaper_verify(scope: "section"|"master"|"item", target: str | None = None,
              start_s=None, end_s=None, baseline: "target"|"previous" = "target",
              plan_id: str | None = None) -> dict
    Рендер участка, дельта к цели или к прошлой версии, вердикт
    (improved / worse / unchanged), запись в журнал. Обязателен после записи.

reaper_journal(action: "head"|"append"|"read", entry: dict | None = None,
               limit: int = 20) -> dict
    Append-only JSONL на проект: что меняли, чем кончилось, что откатили.

reaper_render(scope: "section"|"master"|"stem", track_guids=None,
              start_s=None, end_s=None, format: str = "wav24", path=None) -> dict
    Стемы нужны и измерениям по ролям, и модели-слушателю.

reaper_compare(a: str, b: str, scope: "section"|"master" = "section") -> dict
    Null-тест, дельты по полосам, корреляция, длина в сэмплах. Отличает «лучше» от «по-другому».

reaper_listen(target: str, start_s=None, end_s=None, mode: "describe"|"question" = "describe",
              question=None, engine: "ossicle"|"flamingo"|"moss" = "ossicle") -> dict
    Текст о фрагменте + измеренные факты. Результат хранится как аннотация к адресу.
```

### 3.2 Существующие инструменты (19)

`reaper_session`, `reaper_capabilities`, `reaper_api_search`, `reaper_api_call`,
`reaper_action`, `reaper_project`, `reaper_analyze`, `reaper_mix_evidence`,
`reaper_edit_map`, `reaper_edit`, `reaper_save`, `reaper_release`,
`reaper_spatial_status`, `reaper_spatial_analyze`, `reaper_spatial_timeline`,
`reaper_timeline_context`, `reaper_flamingo_status`, `reaper_flamingo_describe`,

Их не трогаем: они делают тяжёлое (анализ, модели, рендер-захват) и остаются
специализированными. Новые тулы связывают их результаты по адресам.

## 4. Грамматика путей

```
/project/{name,rate,length,time_selection,render/settings}
/tempo/{marker/{i}/{bpm,time_s,timesig}, grid}
/track/{guid}/{name,volume,pan,mute,solo,phase,folder_depth,parent,color,height,automation_mode}
/track/{guid}/send/{i}/{dest_guid,volume,pan,mode}
/track/{guid}/fx/{i}/{name,bypass,offline,preset,param/{j},chunk}
/master/fx/{i}/...
/item/{guid}/{position,length,mute,lock,fade/in,out,shape,group}
/take/{guid}/{volume,pan,playrate,pitch,channel_mode,source_offset,name,source_path}
/track/{guid}/envelope/{pan,volume,width,param/{j}}/{points,mode,visible}
/region/{i}/{start,end,name,render}
/marker/{i}/{time_s,name}
/item/{guid}/midi/{notes,quantize,transpose}
/take/{guid}/midi/notes
```

Путь читается и пишется одинаково: `reaper_state` отдаёт значение, `reaper_apply` принимает
новое. Ноты MIDI — массив `[{start_s, length_s, pitch, velocity, channel}]`, и его можно
писать целиком или патчем (`ops` по индексам).

Значения: число, bool, строка, массив точек `[{time_s, value, shape}]`, объект вставки FX.
Для параметров FX три представления: `normalized` (0..1), `real` (единицы плагина), `display`
(строка). Без этого «поставь 3 дБ» не переводится в запись.

## 5. Состояние: что обязано читаться

| объект | поля |
|---|---|
| проект | имя, путь, rate, длина, ревизия, настройки рендера, выделение времени |
| темп | карта с точками (время, BPM, размер), сетка |
| дорожка | имя, громкость, панорама, mute/solo, фаза, папка/родитель, цвет, автоматизация, вход |
| FX | имя, guid, bypass, offline, пресет, число параметров, параметры (normalized/real/display) |
| посылы | назначение, уровень, панорама, режим (post/pre) |
| айтем | позиция, длина, mute, lock, фейды, форма, группа |
| тейк | громкость, панорама, playrate, pitch, каналы, смещение источника, путь файла |
| конверты | точки (время, значение, форма), режим, видимость |
| маркеры/регионы | время/границы, имя, флаги рендера |
| MIDI | ноты с позицией/длиной/каналом/velocity — чтение и запись |

## 6. Измерения и цели

Матрица уже существует: по каждому источнику (все дорожки + мастер) клетка 100 мс с
`rms_db, peak, crest_db, attack_s, decay_db, flux_db, zcr, bands[25], erb[], centroid_hz,
spread_hz, flatness, rolloff_hz, f0_hz, note, hnr_db, chroma[12], harm, inharm, formants,
decay_bands, coherence, corr, width, pan, low_db, mid_db, high_db, hits, wall`.
Отдельный проход 10 мс даёт огибающую и частоту атак (тремоло/дробь).

Чего не хватает:

1. **Адрес у клетки**: (track_guid, cell_index, start_sample) — чтобы клетка совпадала с путём.
2. **Роллы**: (роль, секция) → медиана/экстремумы/число клеток вне допуска.
3. **Цели**: (роль, секция, метрика) → значение, источник (какой референс), допуск.
4. **Дельта на уровне клеток**, а не средних по треку.
5. **Сжатие по значимости** для чтения: на секцию 3–5 чисел, которые выбились.

Хранение: матрица в `npz`/`parquet` (JSON захлебнётся), в контекст — только роллы,
дельты и адреса.

## 7. Слой слуха

Один инструмент `reaper_listen`, движки переключаются. Ограничения проверены на практике:

- модель не различает технику исполнения; на лид и ритм-гитару выдаёт один и тот же текст;
- сравнение двух клипов — позиционный бин: на двух одинаковых файлах отвечает «Audio 1 громче»;
- числа в промпте не читает (переворачивает знак дельты);
- на соло-стеме отвечает по делу («только гитара, барабанов нет, верх глухой»).

Поэтому: только стем, только один клип, только описание; ответ хранится как аннотация к
адресу и никогда не подменяет замер. 16 кГц — верх и тарелки остаются за измерениями.

## 8. Журнал

JSONL рядом с проектом: `{ts, revision, plan_id, paths, before, after, verify:{metric: delta},
verdict, reason}`. Читается в `context` головой (последние N), целиком — по запросу.
Нужен, чтобы не повторять неудачные правки и видеть, что уже пробовали.

## 9. Инварианты

1. Любая запись — под `expected_revision`, с `plan_id` и откатом.
2. После записи — `reaper_verify`; без него утверждение не делается.
3. Никакой рецептуры в коде: цели и допуски — из `targets` или от вызывающего.
4. Один процесс не трогает UI, не перезапускает REAPER, не убивает его.
5. Модели не влияют на запись: их вывод — текст, а не решение.
6. Ошибка измерения не считается ошибкой проекта: сначала перепроверка, потом вывод.

## 10. Чего не хватает физически

**Бридж (Lua):**

- чтение конвертов (точки, режим, видимость) — сейчас только запись;
- `TrackFX_GetParamEx` (min/max/real/display) в ответе по FX;
- расширенный снимок дорожки (mute, phase, folder, parent, автоматизация), айтема (mute, lock,
  fades, группа), тейка (pitch, каналы, source_path, offsets);
- чтение маркеров/регионов и настроек рендера;
- MIDI: чтение нот есть, добавления нет — нужны `midi.set`, `midi.delete`, `midi.quantize`,
  `midi.transpose` (сейчас только `midi.create`);
- список undo-состояний и undo по метке.

**Сервер:**

- `state`/`apply` поверх существующих kinds и `api_call`;
- `context` — сборка из отчётов анализа, состояния и целей;
- `targets` — хранение и построение целей;
- `verify`, `journal`, `render`, `compare`, `listen`.

**Библиотека:**

- адресация клеток и роллы «роль × секция»;
- дельта к цели на уровне клеток;
- упаковка спектрограмм как ресурс (канал «посмотреть глазами»);
- агрегатор значимости для чтения.

**Конфигурация:**

- карта ролей: 33 дорожки → 12 ролей, хранится рядом с проектом;
- список референсов и разметка их секций.

## 11. Порядок сборки и критерии приёмки

| шаг | что | критерий |
|---|---|---|
| 1 | `state` + `apply` | любое свойство читается и пишется по пути; preview/apply/undo; ревизии соблюдены |
| 2 | расширение бриджа | конверты, параметры с диапазонами, тейки, регионы читаются; снимок полный |
| 3 | `context` + `targets` | один вызов даёт роли, секции, измерения, цели и журнал; цели воспроизводимы |
| 4 | `verify` + `journal` | каждая правка возвращает дельту и вердикт; журнал растёт |
| 5 | `render`/`compare`/`listen` | стемы по ролям, null-тест версий, текст по стему как аннотация |
| 6 | спектрограммы как ресурс | агент смотрит изображение вместо описания словами |

Приёмка всей системы: агент по одному запросу «вот референсы» доводит секцию до целей,
показывая на каждом шаге дельту до/после, и отдаёт рендер с журналом.

## 12. Качество: референсы как распределение, а не как одна цифра

Опыт заменяется **корпусом**. Один референс — это мнение; тридцать — распределение, и в нём
можно измерить, где мы находимся.

### 12.1 Корпус

- Принять N референсов (20–30), привести каждый к одной громкости (LUFS-I) до любых сравнений.
- Разметить секции (вручную или по маркерам/структуре), сопоставить однотипные: припев↔припев.
- **Разложить референсы на стемы** (барабаны/бас/вокал/остальное). Это то, что даёт ролевые
  цели: «бас на 2.1 дБ ниже гитар», а не «в миксе много низа». Стемы референсов считаются
  один раз и кэшируются.
- Для каждой (роль, секция, метрика) собрать выборку значений по всем референсам.

### 12.1.1 Стемы референсов: что отделяется и как не получить мусор

**Отделяется:** вокал, барабаны (и кит внутри: kick/snare/toms/hats/cymbals), бас, «остальное».
**Не отделяется никогда:** дабл-трек L/R, второй слой гитар, скрим против чистого, аккордеон,
«гитара» в плотной секции (это тот же «остальное» с протечкой).

Правила, без которых цели из стемов — мусор:

1. **Один тракт с обеих сторон.** Наши настоящие стемы нельзя сравнивать с сепарированными
   чужими. Наш микс прогоняется через тот же сепаратор, и сравниваются две оценки.
2. **Калибровка протечки на известной истине.** Из наших стемов строятся синтетические миксы,
   прогоняются через сепаратор, считается матрица протечки по полосам. Метрики с протечкой
   выше порога выбрасываются; для остальных берётся поправка или расширенный допуск.
3. **Только робастные метрики.** Из стемов — RMS, соотношения полос, crest, баланс ролей.
   Хвосты, тарелки, ширина и фаза остаются на уровне микса: сепарация врёт там сильнее всего.
4. **Пул по корпусу.** Медиана по 20–30 референсам гасит случайные ошибки; систематические
   снимаются пунктом 2.
5. **Маркировка доверия.** У каждой ячейки цели — `reliable: true|false` и число наблюдений.
   Цели с `reliable: false` в `quality` не входят.

Протокол: 8–10 наших фрагментов → 3–5 синтетических миксов → сепарация → SDR и матрица
протечки → пороги → сепарация всех референсов (кэш по хешу) → цели только по прошедшим.

### 12.2 Цель — интервал, а не точка

Для каждой ячейки корпуса хранить: медиану, MAD (робастный разброс), 10/50/90-й процентили
и число наблюдений. Допуск = 10–90-й процентили. Мы «в цели», когда попадаем в интервал;
«насколько хорошо» = z-оценка: `(наше − медиана) / MAD`.

Это снимает главную проблему одиночной цели: два хороших референса противоречат друг другу,
и попадание в один = промах по другому. В распределении противоречие становится шириной.

### 12.3 Объективная функция

```
quality = 1 − Σ w_i · |z_i| / Σ w_i
```

где `z_i` — z-оценки по метрикам (полосы, crest, ширина, баланс ролей, маскировка, LUFS),
`w_i` — веса приоритетов (низ-мид, присутствие, динамика, ширина, моно). Веса — единственное
место, где живёт вкус, и они задаются один раз на жанр/проект, а не на каждую правку.

Правка принимается только если `quality` выросла **и** ни один z не вышел за пределы
3·MAD в худшую сторону. Иначе откат.

### 12.4 Поиск, а не угадывание

Вместо «половина дельты» — генерация кандидатов и выбор лучшего:

1. по самой отклонённой метрике построить 3–5 кандидатов (разные величины/типы обработки);
2. отрендерить участок для каждого (секция 20–30 с, ~1–2 с на рендер);
3. посчитать `quality` и гейты;
4. принять лучшего, остальных отбросить, записать в журнал.

Рендер секции дешёвый, поэтому 10–20 кандидатов на шаг — норма. Это и есть прямой путь:
не «я знаю, насколько крутить», а «перебрал и измерил».

### 12.5 Гейты (не пропускать правку)

- моно-совместимость: корреляция не ниже 10-го процентиля корпуса;
- клиппинг: ни одного сэмпла на 0 dBFS, true peak выше −1 dBTP;
- динамика: crest/PLR не ниже 10-го процентиля корпуса;
- фаза: нет провалов в критических полосах ниже порога корпуса;
- консистентность: изменение в одной секции не сдвигает другую больше, чем разброс корпуса.

### 12.6 Проверка на отложенном референсе

Цели строятся по N−1 референсам, проверка — на оставшемся (leave-one-out). Если результат
устойчиво попадает в интервал отложенного, значит цели не подогнаны под два трека. Иначе
корпус мал или неоднороден — и это видно до того, как микс испорчен.

### 12.7 Критерий остановки

Останавливаемся, когда одновременно:

1. все z в пределах 1.5 (или все метрики внутри 10–90 процентилей);
2. ни один гейт не провален;
3. последние три правки дали прирост `quality` меньше 0.5% (насыщение);
4. отложенный референс не выбивается.

Дальше — не «докрутить», а отдать на слух: ушам решать то, чего нет в прокси.

### 12.8 Разнообразие секций

«Разнообразие» тоже берётся из корпуса: разница между припевом и куплетом по ширине, плотности
и пространству считается по референсам как распределение, и наша задача — попасть в него,
а не выдумать. Одинаково звучащие секции = отклонение по этой метрике, а не «мнение».

## 13. Дополнения к спеке (из разбора пробелов)

### 13.1 Маршрутизация

- `/track/{guid}/{parent,folder_depth,channels}` — иерархия папок и ширина канала;
- `/track/{guid}/send/{i}/{mode,pre_fx,source_channels}` — режим и откуда берётся сигнал;
- `/track/{guid}/fx/{i}/pins` — карта входов/выходов плагина (1/2→3/4): без неё невозможен
  сайдчейн бочка→бас;
- `/track/{guid}/hardware_out/{i}` — аппаратные выходы.

### 13.2 Доставка

`reaper_render` должен покрывать: секцию, мастер, стемы **с мастер-обработкой и без**, tail,
dither при 16 бит, частоту, битовую глубину; true peak в отчёте; очередь рендера и
bounce-in-place, freeze/unfreeze дорожки.

### 13.3 Айтемы и автоматизация

- `/item/{guid}/{gain,normalize,crossfade/{len,shape}}`, take FX и item FX;
- режимы автоматизации (`read/touch/latch/write`) и формы точек (tension);
- автоматизация параметров плагинов как отдельная сущность.

### 13.4 Измерения, которых нет

LRA и short-term LUFS; true peak и число сэмплов на 0 dBFS; crest по полосам; ширина по
полосам; плотность атак; затухание хвоста и его стереоширина; спектральный наклон (tilt);
маскировка по парам источников, привязанная к адресам.

### 13.5 Процесс

- **кэш**: анализ по хешу файла, инкрементальный пересчёт только изменённой секции;
- **версии**: сравнение двух ревизий проекта (что изменилось), возврат к версии, ветки
  экспериментов;
- **отчёт**: что меняли, дельты до/после, что откатили, итоговый `quality`.

## 14. Что остаётся за человеком

- выбор корпуса референсов (какие записи считаются эталоном);
- веса приоритетов;
- финальное «это звучит как надо» — после того как все z внутри интервалов.

Всё остальное закрывается: попадание в распределение — измеримо, гейты — проверяемы,
перебор кандидатов — дешёвый, отложенная проверка — объективная.

## 15. Замены и слияния (без дублей)

Два пути чтения состояния и два пути записи — это два источника правды. Поэтому:

| старый | новый | вердикт |
|---|---|---|
| `reaper_project` | `reaper_state` | заменить |
| `reaper_edit` | `reaper_apply` | заменить; `reaper_edit` остаётся внутренней реализацией, не инструментом |
| `reaper_spatial_analyze` | `reaper_listen(engine="ossicle")` | заменить |
| `reaper_flamingo_describe`, `reaper_flamingo_ask` | `reaper_listen` | заменить (движок параметром) |
| `reaper_spatial_status`, `reaper_flamingo_status` | `reaper_models_status` | слить |
| `reaper_analyze`, `mix_evidence`, `edit_map` | — | оставить: производные вычисления |
| `reaper_spatial_timeline`, `timeline_context` | — | оставить: DSP и текст аранжировки |
| `api_call`, `api_search`, `capabilities`, `action` | — | оставить: обнаружение и escape hatch |
| `reaper_session`, `reaper_release`, `reaper_save` | — | оставить: здоровье, артефакты, необратимое действие |

Правило на будущее: новый инструмент добавляется только если он **вычисляет** то, чего нет
в состоянии (анализ, рендер, модель). Если он просто читает или пишет свойство — это путь,
а не тул.



## 16. Политики по умолчанию (не отсутствие возможностей)

Шлюз умеет всё перечисленное ниже; включается запросом и записывается в журнал с причиной.

- Аранжировка **записанных** инструментов по умолчанию не меняется: перестановки, удаления,
  «подклейки» живых дублей — только по явному указанию.
- **MIDI пишется свободно**, когда попросили: новые ноты, правка существующих, длина,
  velocity, канал, квантизация, транспозиция. Это полноценная часть поверхности, а не
  исключение.
- Сэмплирование, замена ударов, дублирование партий — допустимы по команде.
- Не делается без прямого запроса: работа через UI и скриншоты, перезапуск или убийство
  REAPER, «какой плагин стоит у референса» (из звука выводится функция обработки, не модель),
  чтение нот из аудио без транскрипции (для нот есть MIDI проекта).
