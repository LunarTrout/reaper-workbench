# AI mix surface — спецификация шлюза REAPER Workbench

Документ описывает, каким должен быть MCP-шлюз и библиотека, чтобы агент мог выполнить
всю работу с треком: свести, обработать, автоматизировать, отмастерить и проверить —
имея только состояние проекта, референсы и измерения.

Границы: **аранжировка записанных инструментов не меняется** (нет новых партий, перестановок,
удалений). Всё остальное — обработка, уровни, панорама, пространство, динамика, автоматизация,
мастеринг, выравнивание — в области работы.

## 1. Три принципа

1. **Адресация вместо операций.** Любое свойство проекта читается и пишется по пути.
   Новое свойство не требует нового инструмента.
2. **Цели из референсов.** Допуски и целевые значения приходят из референсных записей
   (пер-метрический выбор, не среднее по больнице), а не из зашитых констант.
3. **Проверка числом.** После каждой записи — рендер участка и дельта к цели или к
   предыдущей версии. Утверждение без замера не делается.

## 2. Слои шлюза

| слой | назначение | статус |
|---|---|---|
| Сессия и адресация | чтение/запись по путям, батчи, ревизии | **новый** (`state`, `apply`) |
| Контекст | один бандл «всё про трек» для загрузки в голову | **новый** (`context`) |
| Цели | референсы → цели по (роль, секция, метрика) | **новый** (`targets`) |
| Проверка | рендер → дельта → вердикт → журнал | **новый** (`verify`, `journal`) |
| Измерения | матрица 100 мс по источникам, маскировка, ширина | есть (`analyze`, `mix_evidence`, `spatial_timeline`, `timeline_context`, `edit_map`) |
| Слух | текст о фрагменте от аудиомодели | есть частично (`spatial_*`, `flamingo_*`) → сводится в `listen` |
| Рендер и доставка | секция/мастер/стем, сравнение версий | **новый** (`render`, `compare`; `save` есть) |
| Обнаружение | каталог API, поиск, произвольный вызов, экшены | есть (`capabilities`, `api_search`, `api_call`, `action`) |

## 3. Полная поверхность инструментов

### 3.1 Универсальное ядро (новое)

```
reaper_state(paths: list[str] | None = None, scope: str = "project",
             expected_revision: dict | None = None) -> dict
    paths=None → индекс дерева: какие объекты есть и по каким адресам.
    paths=[...] → значения с единицами; для параметров FX — normalized, real, display.

reaper_apply(ops: list[{path: str, value: Any}], mode: "preview"|"apply"|"undo",
             expected_revision: dict, plan_id: str | None = None,
             reason: str | None = None) -> dict
    preview → before/after по каждому пути, проект не меняется.
    apply   → одна транзакция под expected_revision, возвращает новую ревизию и plan_id.
    undo    → откат по plan_id при совпадении ревизии.

reaper_context(sections: "auto" | list, refs: list[str] | None = None,
               detail: "map" | "full" = "map") -> dict
    Роли и шины, секции, FX-цепочки, карта измерений «роль × секция», цели, голова журнала.
    Это то, что агент загружает при старте и держит в контексте.

reaper_targets(action: "register"|"build"|"list"|"compare", refs=None, sections=None,
               weights: dict | None = None) -> dict
    register — принять референсы (путь, громкость, разметка секций).
    build    — построить цели по (роль, секция, метрика): значение, источник, допуск, вес.
    compare  — текущее против целей, без правок.

reaper_verify(scope: "section"|"master"|"item", target: str | None = None,
              start_s=None, end_s=None, baseline: "target"|"previous" = "target",
              plan_id: str | None = None) -> dict
    Рендер участка, дельта к цели или к прошлой версии, вердикт
    (improved / worse / unchanged), запись в журнал. Обязателен после записи.

reaper_journal(action: "head"|"append"|"read", entry: dict | None = None,
               limit: int = 20) -> dict
    Append-only JSONL на проект: что меняли, чем кончилось, что откатили.

reaper_render(scope: "section"|"master"|"stem", track_guids=None,
              start_s=None, end_s=None, format: str = "wav24", path=None) -> dict
    Стемы нужны и измерениям по ролям, и модели-слушателю.

reaper_compare(a: str, b: str, scope: "section"|"master" = "section") -> dict
    Null-тест, дельты по полосам, корреляция, длина в сэмплах. Отличает «лучше» от «по-другому».

reaper_listen(target: str, start_s=None, end_s=None, mode: "describe"|"question" = "describe",
              question=None, engine: "ossicle"|"flamingo"|"moss" = "ossicle") -> dict
    Текст о фрагменте + измеренные факты. Результат хранится как аннотация к адресу.
```

### 3.2 Существующие инструменты (19)

`reaper_session`, `reaper_capabilities`, `reaper_api_search`, `reaper_api_call`,
`reaper_action`, `reaper_project`, `reaper_analyze`, `reaper_mix_evidence`,
`reaper_edit_map`, `reaper_edit`, `reaper_save`, `reaper_release`,
`reaper_spatial_status`, `reaper_spatial_analyze`, `reaper_spatial_timeline`,
`reaper_timeline_context`, `reaper_flamingo_status`, `reaper_flamingo_describe`,
`reaper_flamingo_ask`.

Их не трогаем: они делают тяжёлое (анализ, модели, рендер-захват) и остаются
специализированными. Новые тулы связывают их результаты по адресам.

## 4. Грамматика путей

```
/project/{name,rate,length,time_selection,render/settings}
/tempo/{marker/{i}/{bpm,time_s,timesig}, grid}
/track/{guid}/{name,volume,pan,mute,solo,phase,folder_depth,parent,color,height,automation_mode}
/track/{guid}/send/{i}/{dest_guid,volume,pan,mode}
/track/{guid}/fx/{i}/{name,bypass,offline,preset,param/{j},chunk}
/master/fx/{i}/...
/item/{guid}/{position,length,mute,lock,fade/in,out,shape,group}
/take/{guid}/{volume,pan,playrate,pitch,channel_mode,source_offset,name,source_path}
/track/{guid}/envelope/{pan,volume,width,param/{j}}/{points,mode,visible}
/region/{i}/{start,end,name,render}
/marker/{i}/{time_s,name}
/item/{guid}/midi/notes
```

Значения: число, bool, строка, массив точек `[{time_s, value, shape}]`, объект вставки FX.
Для параметров FX три представления: `normalized` (0..1), `real` (единицы плагина), `display`
(строка). Без этого «поставь 3 дБ» не переводится в запись.

## 5. Состояние: что обязано читаться

| объект | поля |
|---|---|
| проект | имя, путь, rate, длина, ревизия, настройки рендера, выделение времени |
| темп | карта с точками (время, BPM, размер), сетка |
| дорожка | имя, громкость, панорама, mute/solo, фаза, папка/родитель, цвет, автоматизация, вход |
| FX | имя, guid, bypass, offline, пресет, число параметров, параметры (normalized/real/display) |
| посылы | назначение, уровень, панорама, режим (post/pre) |
| айтем | позиция, длина, mute, lock, фейды, форма, группа |
| тейк | громкость, панорама, playrate, pitch, каналы, смещение источника, путь файла |
| конверты | точки (время, значение, форма), режим, видимость |
| маркеры/регионы | время/границы, имя, флаги рендера |
| MIDI | ноты с позицией/длиной/каналом/velocity |

## 6. Измерения и цели

Матрица уже существует: по каждому источнику (все дорожки + мастер) клетка 100 мс с
`rms_db, peak, crest_db, attack_s, decay_db, flux_db, zcr, bands[25], erb[], centroid_hz,
spread_hz, flatness, rolloff_hz, f0_hz, note, hnr_db, chroma[12], harm, inharm, formants,
decay_bands, coherence, corr, width, pan, low_db, mid_db, high_db, hits, wall`.
Отдельный проход 10 мс даёт огибающую и частоту атак (тремоло/дробь).

Чего не хватает:

1. **Адрес у клетки**: (track_guid, cell_index, start_sample) — чтобы клетка совпадала с путём.
2. **Роллы**: (роль, секция) → медиана/экстремумы/число клеток вне допуска.
3. **Цели**: (роль, секция, метрика) → значение, источник (какой референс), допуск.
4. **Дельта на уровне клеток**, а не средних по треку.
5. **Сжатие по значимости** для чтения: на секцию 3–5 чисел, которые выбились.

Хранение: матрица в `npz`/`parquet` (JSON захлебнётся), в контекст — только роллы,
дельты и адреса.

## 7. Слой слуха

Один инструмент `reaper_listen`, движки переключаются. Ограничения проверены на практике:

- модель не различает технику исполнения; на лид и ритм-гитару выдаёт один и тот же текст;
- сравнение двух клипов — позиционный бин: на двух одинаковых файлах отвечает «Audio 1 громче»;
- числа в промпте не читает (переворачивает знак дельты);
- на соло-стеме отвечает по делу («только гитара, барабанов нет, верх глухой»).

Поэтому: только стем, только один клип, только описание; ответ хранится как аннотация к
адресу и никогда не подменяет замер. 16 кГц — верх и тарелки остаются за измерениями.

## 8. Журнал

JSONL рядом с проектом: `{ts, revision, plan_id, paths, before, after, verify:{metric: delta},
verdict, reason}`. Читается в `context` головой (последние N), целиком — по запросу.
Нужен, чтобы не повторять неудачные правки и видеть, что уже пробовали.

## 9. Инварианты

1. Любая запись — под `expected_revision`, с `plan_id` и откатом.
2. После записи — `reaper_verify`; без него утверждение не делается.
3. Никакой рецептуры в коде: цели и допуски — из `targets` или от вызывающего.
4. Один процесс не трогает UI, не перезапускает REAPER, не убивает его.
5. Модели не влияют на запись: их вывод — текст, а не решение.
6. Ошибка измерения не считается ошибкой проекта: сначала перепроверка, потом вывод.

## 10. Чего не хватает физически

**Бридж (Lua):**

- чтение конвертов (точки, режим, видимость) — сейчас только запись;
- `TrackFX_GetParamEx` (min/max/real/display) в ответе по FX;
- расширенный снимок дорожки (mute, phase, folder, parent, автоматизация), айтема (mute, lock,
  fades, группа), тейка (pitch, каналы, source_path, offsets);
- чтение маркеров/регионов и настроек рендера;
- чтение MIDI-нот;
- список undo-состояний и undo по метке.

**Сервер:**

- `state`/`apply` поверх существующих kinds и `api_call`;
- `context` — сборка из отчётов анализа, состояния и целей;
- `targets` — хранение и построение целей;
- `verify`, `journal`, `render`, `compare`, `listen`.

**Библиотека:**

- адресация клеток и роллы «роль × секция»;
- дельта к цели на уровне клеток;
- упаковка спектрограмм как ресурс (канал «посмотреть глазами»);
- агрегатор значимости для чтения.

**Конфигурация:**

- карта ролей: 33 дорожки → 12 ролей, хранится рядом с проектом;
- список референсов и разметка их секций.

## 11. Порядок сборки и критерии приёмки

| шаг | что | критерий |
|---|---|---|
| 1 | `state` + `apply` | любое свойство читается и пишется по пути; preview/apply/undo; ревизии соблюдены |
| 2 | расширение бриджа | конверты, параметры с диапазонами, тейки, регионы читаются; снимок полный |
| 3 | `context` + `targets` | один вызов даёт роли, секции, измерения, цели и журнал; цели воспроизводимы |
| 4 | `verify` + `journal` | каждая правка возвращает дельту и вердикт; журнал растёт |
| 5 | `render`/`compare`/`listen` | стемы по ролям, null-тест версий, текст по стему как аннотация |
| 6 | спектрограммы как ресурс | агент смотрит изображение вместо описания словами |

Приёмка всей системы: агент по одному запросу «вот референсы» доводит секцию до целей,
показывая на каждом шаге дельту до/после, и отдаёт рендер с журналом.

## 12. Не-цели

- изменение аранжировки записанных инструментов;
- дописывание партий, сэмплов, «подклейка» чужих ударов;
- работа через UI и скриншоты;
- обещание «какой плагин стоит у референса» — из звука выводится функция обработки, не модель;
- чтение нот из аудио без транскрипции (для нот есть MIDI проекта).
