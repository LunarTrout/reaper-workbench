# Методика измерения микса против корпуса референсов

Дата: 2026-11-12. Область: инструментальная музыка, преимущественно металл; агент не слышит звук.

**Границы документа.** Здесь нет «формулы качества», фиксированных весов, порогов и канонического
списка метрик для кода. Причина не в осторожности, а в идентифицируемости: при 20–30 референсах и
отсутствии внешнего критерия любая такая формула недоказуема — она либо подгоняет числа, либо
маскирует произвол. Документ задаёт измерительную методику, способ оценивать цели и
неопределённость по корпусу, модель расстояния с оцениваемыми параметрами и протокол валидации.
Скалярная «оценка» — решение проекта, а не методики.

Все числа в коде допускаются только трёх видов:

1. **Определения стандарта** — BS.1770-5, EBU R128, Tech 3341/3342, Annex 2 (true peak).
2. **Оценки по корпусу в рантайме** — центр, масштаб, ковариация, число компонент, k, порог
   отсечения и т. п. Оцениваются на обучающей части и проверяются leave-one-reference-out.
3. **Настройка проекта** — какие измерения включены, какие секции/роли, какая политика
   скаляризации, какой delivery-таргет. Фиксируется в отчёте вместе с результатом.

Всё остальное — константа, которой не место в методике.

---

## 0. Позиция: что здесь называется «качеством»

1. **Валидированной метрики «качества микса» не существует.** В литературе валидированы
   *full-reference* метрики качества кодека/обработки (ViSQOL, PEAQ, CDPAM, HAAQI): они сравнивают
   сигнал с его же деградированной версией и к двум разным песням неприменимы [6–9, 21]. Лучшее
   исключение — *mix clarity через маскирование*: ρ≈0.84 с субъективными оценками на небольшой
   выборке [16]. Это единственный конструкт с опубликованным числом, и его всё равно надо
   перепроверять на своём материале.
2. Поэтому «quality» в проекте — это **не скаляр**, а:
   - вектор измерений по (роль, секция, конструкт);
   - положение этого вектора в распределении корпуса (ранг/перцентиль, а не «0…1»);
   - неопределённость положения (bootstrap/LOO);
   - отдельный список нарушений стандартов/дефектов, которые не смешиваются с «тоном» и «шириной».
3. **Скаляризация — только если проект её требует.** Тогда веса и пороги — оцениваемые параметры
   (из надёжности измерений или внешних предпочтений), а не константы; они валидируются
   leave-one-reference-out и публикуются вместе с результатом. По умолчанию отчёт — вектор.
4. **Корпус — это цель, а не истина.** Если корпус посредственный, любая метрика будет поощрять
   посредственность. Курирование корпуса — часть методики, а не подготовительный шаг.

Что методика обязана гарантировать:

| Гарантия | Как проверяется |
|---|---|
| Измерения соответствуют стандартам | conformance-тесты BS.1770/R128/Tech 3341/3342 |
| Цели не являются шумом | LOO-устойчивость, split-half, bootstrap CI |
| Расстояние не подогнано | nested LOO, leave-one-cluster-out, holdout |
| Реакция на деградации осмысленна | матрица контролируемых деградаций |
| Нет ложной точности | отчёт всегда с неопределённостью и размером корпуса |

## 1. Стандарты: единственные допустимые константы

### 1.1 BS.1770-5 (11/2023)

- K-weighting = 2 биквада: shelf «сферическая голова» (+~4 dB на ВЧ) + RLB high-pass. Коэффициенты
  в рекомендации даны для 48 кГц; для других частот их пересчитывают, сохраняя АЧХ [1].
- Громкость: `L = −0.691 + 10·log10(Σ_i G_i·z_i)`, `z_i` — mean square после K-weighting.
- Веса каналов: L/R/C = 1.0, Ls/Rs = 1.41, LFE = 0.
- Гейтинг: блоки 400 мс, перекрытие 75 %, абсолютный порог −70 LKFS, затем относительный −10 LU.
- Якорь: синус 997 Гц 0 dBFS на одном фронтальном канале → −3.01 LKFS.

### 1.2 EBU R128 / Tech 3341 / Tech 3342

| Величина | Окно | Гейт | Смысл |
|---|---|---|---|
| Integrated (I) | 400 мс, 75 % overlap | −70 LKFS, затем −10 LU | программа целиком |
| Momentary (M) | 400 мс | нет | громкость момента |
| Short-term (S) | 3 с | нет | макро-динамика |
| LRA | 3 с, ≥10 Гц | −70 LKFS, затем −20 LU; p10–p95 | разброс громкости |
| True peak (TP) | 4× oversampling ≥192 кГц | — | интерсэмпловый пик |

R128: программа нормализуется к −23.0 LUFS, TP ≤ −1 dBTP (допуск ±0.3 дБ для 20 кГц) [2].
LRA не рекомендуется для программ короче 1 минуты [2, 3]. Для стриминга ориентиры другие
(Spotify ≈ −14 LUFS, Apple Music ≈ −16 LUFS) [4] — это delivery-политика, не качество.

True peak, Annex 2: ослабление 12.04 дБ, 4× oversampling, 48-tap 4-phase FIR, модуль, +12.04 дБ;
для 96 кГц достаточно 2× [1].

**Практика.** В проекте уже есть `phonometry`: `program_loudness(x, fs)` возвращает `integrated`,
`loudness_range`, `true_peak`, ряды `momentary`/`short_term`, `max_momentary`, `max_short_term`,
`relative_threshold`, `lra_low`, `lra_high`; модуль валидирован по Tech 3341/3342 [10]. Это
закрывает стандартный слой без pyloudnorm/pyebur128. Текущие `_loudness_blocks()` (pyloudnorm, без
TP) и `reference_delta.py` (crest по sample peak) надо перевести на него.

## 2. Инвентарь измерений

Это **инвентарь**, а не конфиг. Какое подмножество включено в конкретную задачу — настройка
проекта; она фиксируется в отчёте. У каждого измерения есть конструкт, стандарт/формула, стоимость
и **уровень доказательности**:

- **A** — определено стандартом, воспроизводимо, не зависит от вкуса.
- **B** — перцептивно мотивировано, есть опубликованная валидация (хотя бы на малой выборке).
- **C** — описатель контента/стиля; полезен для диагностики и выбора референсов, не для оценки.
- **D** — не измеряет качество; использовать нельзя (кроме как контекст).

### 2.1 Стандартный слой (A)

| Измерение | Конструкт | Формула/окно | Библиотека | Цена |
|---|---|---|---|---|
| LUFS I | громкость программы | BS.1770-5 Annex 1 | `phonometry.broadcast` | O(N) |
| LRA | макро-динамика | 3 с/10 Гц, гейты −70/−20, p10–p95 | `program_loudness` | O(N) |
| M/S-ряды | распределение громкости | 400 мс / 3 с | `program_loudness` | O(N) |
| TP | интерсэмпловый пик | Annex 2, 4×/48-tap | `true_peak_level` | O(N) |
| PLR | транзиентный запас | `TP − I` | numpy | O(1) |
| PSR | локальная переспрессованность | `TP_sec − max(S_sec)` | numpy | O(1) |
| Клиппинг-раны | цифровой дефект | runs `|x| ≥ FS`, длина/число | numpy | O(N) |

### 2.2 Перцептивно мотивированные (B)

| Измерение | Конструкт | Формула/окно | Библиотека | Цена |
|---|---|---|---|---|
| Masking SMR | разборчивость/ясность | по кадрам и ERB: `SMR = 10log10(E_target / T_maskers)`; `T` — MPEG Model II (spreading + tonality) по сумме остальных источников; агрегаты распределения | своя реализация ISO 11172-3 Annex D | O(S·F·B) |
| Парный SMR | кто кого маскирует | тот же расчёт, маскер — один источник | своя | O(S²·F·B) |
| Crest по полосам | переспрессованность в полосе | распределение peak/RMS в октавной полосе | scipy | O(N·B) |
| Spectral tilt | тембр/яркость | OLS уровня полос на `log2(f)`; 100 Гц–10 кГц | numpy | O(B) |
| 1/3-окт. CLR | тональный баланс | `clr_b = ln P_b − mean(ln P)`; композиционные данные | numpy | O(N log N) |
| Side/mid по полосам | частотно-зависимая ширина | `10log10(P_side,b/P_mid,b)` | numpy | O(N·B) |
| Корреляция по полосам | фаза/моно | `r_b`, отдельно LF | numpy | O(N·B) |
| Mono loss | перевод в моно | `LUFS(M) − LUFS(stereo)` | `program_loudness` | 2×O(N) |
| Decay/T30 | хвост/гулкость | Schroeder integration после офсета | numpy/scipy | O(N) |
| Tail width | стерео хвоста | side/mid в окне после офсета | numpy | O(N) |
| Attack density/sharpness | панч/атака | onset rate (нормировать на beat), rise time, наклон | librosa/своя | O(N) |
| Zwicker N5, sharpness | перцептивная громкость/резкость | ISO 532-1 / DIN 45692 | `phonometry.psychoacoustics` | O(N) |

Почему именно эти: они либо стандартизованы, либо имеют опубликованный перцептивный конструкт, либо
являются level-инвариантными после нормировки. CLR обязателен для полос: пять грубых band-ratio —
композиционные данные с суммой 1; по отдельности они дают ложные корреляции и вырожденную
ковариацию [12].

### 2.3 Описатели контента (C)

`centroid`, `spread`, `flatness`, `rolloff`, `ZCR`, `chroma`, `key`, `f0`, `HNR`,
`harmonics/inharmonic`, `hits`, `coherence`, `wall`, `SII proxy`, `width timeline`.

Их роль: стилевой вектор для кластеризации/k-NN, выбор референсов, объяснение отклонений. В модель
расстояния они не входят: они описывают материал, а не продакшн, и сильно коррелируют с уровнем.

### 2.4 Что не является метрикой качества (D)

| Метрика | Почему |
|---|---|
| абсолютный LUFS | платформенная нормировка; громче ≠ лучше |
| сырой crest factor | предпочтение к компрессии слабое и жанрово-зависимое [5] |
| DR meter | зависит от гейтинга и шума |
| один band-ratio | композиционные данные, сумма = 1 |
| SII proxy | речевая разборчивость нерелевантна инструментальному металлу |
| «похожесть на референс» без конструкции | совпадение чисел ≠ качество |

### 2.5 Что реально предсказывает воспринимаемое качество

| Конструкт | Доказательность | Вывод |
|---|---|---|
| Ясность/маскировка | ρ≈0.84, малая выборка, 10-с стимулы [16] | сильнейший кандидат; перепроверять на своём материале |
| Громкость/компрессия | стандарт измерения есть; предпочтение — смешанные данные [5] | измерять, но не делать «больше динамики = лучше» |
| Тональный баланс | практика reference-matching; формальной валидации мало | главная рабочая ось, но конформность, не качество |
| Ширина/пространство | больше про перевод/моно, чем про предпочтение | диагностика, не цель |
| Тембр/яркость (centroid и пр.) | коррелирует с «яркостью», не с предпочтением | описатель |
| Всё остальное (f0, chroma, hits) | контент | не качество |

Отдельно: **Hjortkjær & Walther-Hansen (2014)** не нашли значимого предпочтения менее
скомпрессированных версий; эффект компрессии мал по сравнению с громкостью и клиппингом [5].
Поэтому цель по PLR/LRA должна быть жанрово-условной и оцениваться по корпусу, а не задаваться
лозунгом.

| **audiobox-aesthetics** | PQ/CE/CU/PC | 16 кГц mono, окна 10 с | cc-by-4.0 (веса) [13] | GPU; на V100 **не bf16**, fp16/fp32 | слабый внешний валидатор PQ | 16 кГц режет «воздух»; CE — контент |

Общее ограничение: full-reference модели отвечают на вопрос «насколько это хуже своего чистого
оригинала», а не «насколько это хороший микс». Их место:
- проверить, что правка не ухудшила сигнал (после EQ/компрессии ViSQOL/CDPAM не просели);
- построить лестницу деградаций (§7.2);
- дать слабую внешнюю метку (§7.3).

Настраивать веса модели под них нельзя: это заменит одну непроверенную цель другой.

`audiobox-aesthetics` на V100: в `infer.py` default `precision="bf16"`, SM 7.0 bf16 не умеет —
нужен fp16/fp32. Вход 16 кГц mono, окна 10 с [13].

## 4. Tonal matching: принципы, а не рецепт

### 4.1 Как устроен Matchering 2.0 (факты)

| Стадия | Что делает | Следствие |
|---|---|---|
| Level | куски ≤15 с, RMS кусков выше среднего, матч RMS mid/side | игнорирует LUFS-гейтинг; смещение к припеву |
| Spectrum | FFT 4096, boxcar, средняя magnitude, отношение ref/target | нет перцептивного взвешивания; один средний спектр |
| Smoothing | лог-частотная сетка ×4, LOWESS frac 0.0375 | может размывать узкие резонансы |
| Filter | `irfft` + Hann → zero-phase FIR 4096, mid/side отдельно | pre-ringing на транзиентах; side-EQ усиливает шум |
| Correction | 4 итерации RMS | громкость «плывёт» |
| Limiter | собственный brickwall | меняет PLR/динамику |
| Лицензия | GPL-3.0 | «заразна» для закрытого продукта |

Источник: [15].

### 4.2 Принципы тонального матчинга

1. **Цель — оценка по корпусу, не по одному треку.** Для нашего микса брать локальную подвыборку
   референсов (k ближайших в стилевом пространстве; k выбирается по LOO, не фиксируется) и
   оценивать по ней медиану и разброс уровня полос. Один референс переносит свою аранжировку.
2. **Полосы.** 1/3-октава для отчёта, ERB для маскировки. Уровни — из K-weighted спектра, иначе
   ВЧ переоценены.
3. **Статистика.** Медиана по активным кадрам (активность определяется по S-громкости относительно
   распределения трека, а не по фиксированному порогу), отдельно mid и side.
4. **Величина коррекции.** Не фиксированный предел в дБ, а функция от оценённого разброса полос в
   корпусе и неопределённости измерения: коррекция ограничивается тем, что статистически отличимо
   от корпусного разброса. Политика (консервативная/агрессивная) — настройка проекта.
5. **Фильтр.** Minimum-phase FIR или каскад peaking/shelf биквадов. Zero-phase даёт pre-ringing,
   слышимый на кик/снейр. Group delay проверять в НЧ.
6. **Динамика.** После EQ — одна нормировка громкости; LRA/PLR не матчить. Проверять, что изменение
   LRA/PLR не превышает неопределённости их измерения (оценка по повторным замерам/секциям), а не
   фиксированный допуск.
7. **Валидация.** Синтетика: внести известный tilt, проверить восстановление в пределах
   измерительной ошибки; проверить, что LRA/PLR не изменились значимо.

Ограничение: тональный баланс — конформность, не качество. Он не знает про аранжировку, грув и
художественную задачу.

## 5. Статистика корпуса: оценивание, а не рецепт

### 5.1 Оценки центра и масштаба

| Вопрос | Наивно | Корректно | Почему |
|---|---|---|---|
| Центр | mean | median | один громкий мастер сдвигает mean |
| Масштаб | std | MAD (со своим consistency factor) | устойчив к 1–2 выбросам [18] |
| Масштаб при малом n | MAD как есть | shrinkage к приору, приор оценивается по LOO/CV | относительная SE(MAD) ≈ 1.858/√n: при n=25 это ~37 % |
| Допуск | p10–p90 | распределение + неопределённость | p10 при n=25 — 2–3-й порядок; его CI широк |
| Выбросы | удалить | robust-оценки + jackknife-влияние | нельзя молча удалять «неудобный» трек |

Формулы, которые полезно держать в голове (это свойства оценок, не константы метода):

- `SE(median) ≈ 1.253·σ/√n`. При n=25 это ±0.49σ (95 % CI). Корпус 25 треков даёт цель с
  точностью около ±0.5σ, не лучше.
- `SE(MAD)/MAD ≈ 1.858/√n` → ~37 % при n=25. Поэтому масштаб надо shrinkage-ить; вес приора
  выбирается по LOO, а не назначается.
- Если MAD = 0 (метрика константна), масштаб должен быть ограничен снизу оценкой измерительной
  ошибки, иначе z = ∞.

**Ошибка измерения.** У каждой метрики есть test-retest ошибка (разные окна, секции, повторный
анализ). Её надо оценивать эмпирически и пропагировать: сравнение микса с целью идёт не с точкой,
а с интервалом. Иначе различия в 0.1 дБ будут выглядеть как сигнал. Это классическая
errors-in-variables: без учёта ошибки оценки занижают корреляции и завышают значимость.

### 5.2 Гетерогенность: кластеры и локальные цели

Корпус «металл» — не один жанр. Black metal с лоу-фай-продакшном и современный djent различаются
по всем полосам сильнее, чем хороший и плохой микс внутри одного поджанра. Глобальная медиана по
такому корпусу — среднее между разными эстетиками.

Порядок (все гиперпараметры выбираются по LOO, не фиксируются):

1. **Стилевой вектор** из описателей C (tempo, onset density, tilt, sharpness, LRA, ширина,
   band-shape). Нормировать робастно.
2. **PCA**; число компонент — по CV/LOO (при n=25 реалистичны единицы компонент).
3. **Кластеризация** (иерархическая/Ward или k-means) + bootstrap-стабильность (Jaccard).
   k выбирается по gap statistic/silhouette и проверяется на устойчивость.
4. Если кластеры стабильны — цели по кластеру. Если нет — **k-NN**: для нашего микса брать k
   ближайших референсов в стилевом пространстве, веса — kernel, k — по LOO. Это адаптируется к
   стилю без свободных весов.
5. **Partial pooling** для (роль, секция): если в ячейке мало треков, тянуть к аддитивной модели
   `m_role + m_section − m_grand`; вес приора — по LOO.

### 5.3 Leave-one-reference-out и nested LOO

Базовый протокол:

- для каждого референса `j` строим цели по остальным `n−1`;
- считаем расстояние `D_j` до этих целей;
- получаем эмпирическое распределение `{D_j}` — «облако профессионалов».

Это одновременно калибровка и null-распределение: ранг нового микса среди `{D_j}` — честная
величина, не зависящая от произвольной шкалы.

**Nested LOO обязателен**, если в модели есть настраиваемые параметры (число компонент, k,
регуляризация, веса): внешний цикл — оценка качества, внутренний — выбор параметров. Иначе
параметры подбираются на том же референсе, на котором измеряется качество, и LOO завышает результат.

Дополнительно:
- **leave-one-cluster-out** — строим цели без целого кластера; проверяем, не разваливается ли
  модель на другом стиле;
- **split-half** — две половины корпуса дают две цели; сравниваем их векторы и ранг-корреляцию;
- **jackknife** — влияние каждого референса на цель; если один трек меняет цель сильнее, чем
  разброс корпуса, цель неустойчива.

### 5.4 Размер корпуса и мощность

| n | Мин. значимый r (p<0.05) | r при power 80 % | Что реалистично |
|---|---|---|---|
| 20 | 0.44 | 0.59 | грубые цели, бинарные проверки |
| 25 | 0.40 | 0.54 | цели ±0.5σ, 2–3 кластера |
| 30 | 0.36 | 0.49 | цели ±0.45σ |
| 50 | 0.28 | 0.39 | хвосты, 3–4 кластера |
| 100 | 0.20 | 0.29 | веса, тонкие эффекты |

Вывод: 20–30 референсов не позволяют валидировать тонкую метрику. Если эффект r=0.3, нужно ~85
треков. Поэтому нельзя «подбирать веса» на 25 треках: p >> n. Любая модель с многими параметрами
должна быть регуляризована и проверена nested LOO, а не подогнана.

### 5.5 Множественные сравнения

При 100 метриках и α=0.05 ожидается 5 ложных срабатываний. Меры:
- pre-register измерения, которые войдут в анализ;
- для exploratory — Benjamini–Hochberg FDR [19];
- всегда отчёт effect size (Cliff's delta / rank-biserial), а не только p;
- не менять гипотезу после просмотра данных.

### 5.6 Что проверить на корпусе (аудит)

Обязательный чек-лист перед построением целей. Каждый пункт — с действием при провале.

| # | Проверка | Как | Если провал |
|---|---|---|---|
| 1 | Стадия | микс или мастер у каждого файла | разделить корпуса или ввести stage-offset |
| 2 | Происхождение/качество | откуда трек, кто мастер, внешние признаки | исключить или понизить вес |

| 6 | Дубли/версии | один трек в разных изданиях/ремастерах | оставить одну версию |

| 11 | LOO-распределение | гистограмма `D_j`, хвосты | проверить гетерогенность/ошибки |
| 12 | Стабильность кластеров | bootstrap Jaccard | не дробить корпус, использовать k-NN |

| 14 | Качество разделения источников | confidence/bleed | per-role только как диагностика |
| 15 | Внешний якорь | корреляция с MED/audiobox | если нет — не утверждать «качество» |

## 6. Модель расстояния: параметры оцениваются

### 6.1 Почему фиксированная взвешенная сумма не годится

Текущая идея `q = 1 − Σw|z|/Σw`, `z = (x − median)/MAD` имеет конструктивные дефекты:

1. **Масштаб.** MAD без consistency factor — это 0.6745σ; `|z|=1` соответствует 0.67σ, а не 1σ.
   Допуски и веса несогласованы.
2. **Хвосты.** Линейный штраф неограничен: одна метрика с `z=8` утопит остальные.
3. **Корреляции.** 25 полос — не 25 независимых голосов; сумма |z| многократно считает одну
   «яркость».
4. **Совместность.** Вектор маргинальных медиан — не реальный трек. В многомерном пространстве он
   ближе к корпусу, чем любой референс; «идеальная» точка недостижима и не типична.
5. **Калибровка.** У реального референса score не 1; нет null-распределения.
6. **Гейты.** Клиппинг/TP/моно-провал растворяются в сумме.

Поэтому вместо формулы — **модель расстояния с оцениваемыми параметрами** и отчёт вектором.

### 6.2 Варианты модели

| Вариант | Параметры | Как оцениваются | Когда уместен |
|---|---|---|---|
| A. Регуляризованная ковариация | центр, ковариация, shrinkage | Ledoit–Wolf/графическая лассо; сила регуляризации — по LOO | метрики коррелированы, n≥p хотя бы приблизительно |
| B. Факторная модель/PCA | число компонент, loadings | число компонент по CV/LOO; loadings — на train-фолде | p>n, нужна интерпретируемость |
| C. Обучаемое вложение | веса/сеть, triplet margin, регуляризация | triplet/contrastive на референсах + контролируемых деградациях; nested LOO | есть размеченные пары «лучше/хуже» или деградации |

Во всех вариантах:
- стандартизация (центр/масштаб) оценивается **только на train-фолде**, иначе утечка;
- размерность/регуляризация выбираются по LOO, а не назначаются;
- отчёт включает число параметров, обусловленность матрицы, устойчивость;
- сравнение A/B/C — по LOO-ранг-корреляции с внешним критерием (MED/audiobox/эксперты) и по
  стабильности, а не по «красивости» числа.

### 6.3 Калибровка и отчёт

- Эмпирическое распределение `{D_j}` из LOO — референсная шкала. Для нового микса отчёт:
  `D`, ранг/перцентиль, CI (bootstrap по трекам/секциям), размер корпуса.
- **Не** превращать ранг в «0…1 качество» без внешней калибровки. Ранг — честная величина;
  «0.87» — иллюзия.
- Если проект требует скаляр: веса оцениваются из надёжности измерений (обратная дисперсия/
  inverse-variance) или из внешних предпочтений (регрессия/ранжирование с регуляризацией), затем
  проверяются LOO. Веса и пороги публикуются в отчёте; в коде их нет.
- Неопределённость обязательна: `D ± CI`, а не точка. Для A/B — paired block bootstrap по секциям,
  чтобы не занизить CI из-за автокорреляции кадров.

### 6.4 Что считать «лучше»

`D` говорит «ближе к корпусу», а не «лучше». Для художественного выбора нужен человек или внешний
critic. Метрика может лишь:
- не дать уйти за профессиональный конверт;
- показать, какой конструкт и в какой секции выпадает;
- отличить дефект от стиля.

## 7. Протокол валидации

### 7.1 Уровни

| Уровень | Что проверяет | Тест | Критерий (в относительных терминах) |
|---|---|---|---|
| 0. Измерение | метрики считаются правильно | EBU Tech 3341/3342 test signals; TP на интерсэмпловом пике; сверка с ffmpeg | расхождение в пределах допуска стандарта |
| 1. Оценки | цели не шум | split-half, bootstrap, jackknife, LOO | CI цели уже разброса между треками; ранг устойчив |
| 2. Деградации | расстояние реагирует на то, на что должно | матрица деградаций (§7.2) | монотонный ранг, правильная атрибуция конструкта |
| 3. Внешняя | связь с людьми | MED 2.0, audiobox PQ, listening test | ранг-корреляция с CI, значимо отличная от нуля |
| 4. A/B | две версии различимы | paired block bootstrap | CI не включает ноль; эффект больше измерительной ошибки |

### 7.2 Матрица деградаций

Берём референс (или нейтральный тест-микс) и портим контролируемо. **Величины — дизайн
эксперимента**, выбираются так, чтобы покрыть диапазон ниже/около/выше JND; в коде их быть не
должно.

| Деградация | Направление | Ожидаемо задевает | Ожидание |
|---|---|---|---|
| Gain | ±несколько дБ | ничего после нормировки | инвариантность |
| Tilt | наклон АЧХ | tone | монотонный рост расстояния |
| HP/LP | срез | tone | монотонный рост |
| Компрессия | ratio при том же LUFS | dyn | монотонный рост |
| Лимитирование | выше 0 dBTP | dyn + дефект | появление дефекта |
| Клиппинг | доля семплов | дефект | pass→fail |
| Моно-коллапс | ширина | space | монотонный рост |
| Реверб | wet | space/tail | рост до оптимума, затем рост |
| Маскировка | pad в presence | clarity | монотонный рост |
| Шум | уровень | дефект | pass→fail |
| Ресемпл | ниже Nyquist | tone/дефект | монотонный рост |

Главный тест: если расстояние не реагирует на tilt/клиппинг — оно измеряет не то. Если реагирует
на gain после нормировки — в нём сидит level-confound.

### 7.3 Внешняя валидация

- **Mix Evaluation Dataset 2.0**: ~180 миксов, ~5000 preference ratings [20]. Считать `D` для
  каждого микса против корпуса коммерческих референсов и коррелировать с рейтингами. Ожидание —
  умеренная ранг-корреляция; точное число не задаётся, важен CI и устойчивость знака.
- **audiobox PQ**: слабая метка; коррелировать, не подгонять.
- **Listening test**: если появится возможность — MUSHRA/ABX, loudness-matched, с выборкой, достаточной для запланированного эффекта.
  Это единственный способ валидировать веса, но он вне текущих ограничений.

### 7.4 Null-тесты

| Тест | Ожидание |
|---|---|
| повторный замер того же файла | `ΔD = 0` (детерминизм) |
| две половины одного трека | различие в пределах измерительной ошибки |
| два разных трека с одинаковой обработкой | `D` в пределах облака |
| случайная перестановка целей | наш микс не в хвосте случайно |
| неслышимая правка | изменение меньше измерительной ошибки |
| gain + нормировка | изменение меньше измерительной ошибки |

### 7.5 Защита от подгонки

- nested LOO;
- никакой выбор метрик/параметров на тестовом фолде;
- holdout по трекам, а не по кадрам (кадры одного трека коррелированы);
- holdout по кластерам (проверка переноса на другой поджанр);
- pre-registration гипотез;
- отчёт всех попыток, а не только удачной.

- детерминизм.

## 9. Подводные камни

1. **Mix vs master.** Корпус из мастеров, сравнение с миксом — систематическая ошибка: мастера
   громче, плотнее, лучше по моно [4]. Разделять стадии или вводить stage-offset.
2. **Глобальная медиана по гетерогенному корпусу.** Поджанры различаются сильнее, чем хороший/
   плохой микс. Кластеры или k-NN обязательны.
3. **Level confound.** Тембральные/пространственные метрики считать после нормировки, кроме явно
   level-инвариантных (PLR, tilt, CLR, side/mid, corr).
4. **Маргинальные медианы ≠ совместная цель.** Вектор медиан — не реальный трек; отсюда
   необходимость эмпирической калибровки LOO.
5. **MAD без consistency factor и без нижней границы.** z-скоры уезжают; при MAD=0 — бесконечность.
6. **Коррелированные метрики.** 25 полос — один фактор, а не 25 доказательств.
7. **p10–p90 при n=25.** Это 2–3-й и 23–24-й порядки; доверять нельзя. Использовать распределение
   и неопределённость.
8. **Подгонка весов на 25 треках.** p >> n; веса либо оцениваются с регуляризацией, либо не
   вводятся.
9. **Множественные сравнения.** 100 метрик → 5 ложных на α=0.05; BH-FDR и effect size.
10. **Несовпадение секций.** Сравнивать распределения по типам секций, а не покадрово; только
    секции, представленные в корпусе.
11. **Ошибки разделения источников.** Per-role цели содержат bleed; для расстояния — full-mix,
    per-role — диагностика.
12. **EQ-матчинг убивает динамику/фазу.** Minimum-phase, ограничение коррекции разбросом корпуса,
    проверка LRA/PLR в пределах измерительной ошибки.
13. **Sample peak вместо true peak.** Интерсэмпловый клиппинг не виден; использовать Annex 2.
14. **LRA на коротких секциях.** <60 с — не LRA; использовать S-распределение.
15. **Ширина как «больше = лучше».** Жанрово-зависима; в металле часто уже, чем в поп-музыке.
16. **«Похожесть» ≠ «качество».** Идеальное попадание в медианы может быть безликим.
17. **Нестационарность.** Один трек даёт разный результат на разных секциях; нужен секционный
    вектор, а не одно число.
18. **K-weighting при 44.1 кГц.** Коэффициенты BS.1770 даны для 48 кГц; пересчитывать и проверять.
19. **Корпус — цель, а не истина.** Посредственный корпус поощряет посредственность.
20. **Утечка через выбор метрик.** Если метрика выбрана по корреляции с внешним критерием на всём
    корпусе, LOO завышает. Выбор — только внутри train-фолда.
