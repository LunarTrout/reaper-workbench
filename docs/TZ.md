# ТЗ: что библиотека должна давать агенту

Коротко и полно. Это требования, а не реализация: как именно — в `AI-MIX-SURFACE.md`.

## 1. Задача

Записанный и сведённый «как получилось» трек довести до студийного качества по корпусу
референсов: тон, баланс, динамика, пространство, стерео, эффекты, автоматизация, выравнивание,
мастеринг. Универсально: не «под блэк-метал», а под любой инструментальный проект. Жанровых
констант в коде нет — всё берётся из корпуса референсов и настроек проекта.

## 2. Границы

- Аранжировка **записанных** инструментов не меняется (перестановки, удаления, подклейки) без
  явного указания.
- **MIDI пишется свободно**, когда попросили: ноты, длина, velocity, канал, квантайз, транспозиция.
- Сэмплирование и дубли партий — по команде.
- Не делается никогда: работа через UI/скриншоты, убийство или перезапуск REAPER, обещание
  «какой плагин стоит у референса», чтение нот из аудио без транскрипции.

## 3. Контекст: доступ, а не постоянная загрузка

«Видеть всё» — это не держать в голове весь трек, а **иметь доступ ко всему нужному и не
пропускать проверки**. Требования:

- любые данные проекта и измерений читаются по требованию: состояние, матрица 100 мс по
  источникам, ширина/баланс по времени, маскировка, цели, журнал;
- **дисциплина покрытия**: перед выводом фиксируется, что именно проверено — какой диапазон,
  какие роли, какие метрики. Непроверенное помечается как непроверенное, а не додумывается;
- ни одно утверждение о звуке не делается без артефакта: замера, рендера, картинки или цитаты
  модели с её ограничениями;
- контекст собирается по первому запросу и обновляется после правок; повторно читается только
  то, что изменилось.

## 4. Сведение (всё, что делает человек)

- **Тон**: полосы, наклон, резонансы, муть, жорсткость — по роли и секции.
- **Баланс**: уровни ролей, иерархия (кто ведёт), маскировка, шины и посылы.
- **Динамика**: контроль, склейка, параллельная компрессия, транзиенты, де-эссинг, сайдчейн
  (включая пин-маппинг 1/2→3/4).
- **Пространство**: реверб/дилей по ролям, пре-дилей, EQ на хвосте, глубина; **разнообразие
  секций** — тоже из корпуса, а не из фантазии.
- **Стерео**: расстановка, ширина дабл-трека, M/S, бас в моно, моно-совместимость.
- **Эффекты**: выбор и настройка через параметры плагинов (реальные значения, не только 0..1),
  пресеты, порядок в цепочке, байпас, freeze.
- **Автоматизация**: уровень по фразам, панорама, посылы; режимы и формы точек; параметры плагинов.
- **Мастеринг**: цепочка, LUFS/true peak/PLR из корпуса, клиппинг, дизер, доставка мастер+стемы.

## 5. Выравнивание

Обязательная часть, и ошибаться здесь нельзя.

- **Время**: гитары и вокал (и любой материал) выравниваются по видимым в волне атакам, как это
  делает человек: опорный дубль → поиск того же транзиента в остальных → сдвиг айтема.
  Без квантизации, без растяжения, без изменения грува.
- Проверка после сдвига: корреляция и фаза на стыке, отсутствие гребенчатой фильтрации,
  совпадение атак по времени.
- **Уровень/тон**: ровность роли между секциями — в пределах разброса корпуса, без «прыжков»
  от куплета к припеву без музыкальной причины.
- Критерий: артефактов не слышно и не видно; смещение не больше физически необходимого;
  всё воспроизводимо (журнал смещений).

## 6. Качество: почти гарантированно

- **Корпус** из многих референсов → распределения (медиана, MAD, 10/90 процентили) по
  (роль, секция, метрика), в том числе по стемам референсов с калибровкой протечки.
- **Жанровый фокус (пока):** тяжёлые и сложные жанры — tech death, black, death и близкое.
  Корпус собирается из них; для других жанров меняется корпус, а не код.
- **Оценка выводится из корпуса**: расстояние и отбор признаков оцениваются по референсам
  (ковариация с регуляризацией / обучаемое вложение), допуски — эмпирические перцентили,
  проверка — leave-one-reference-out. Фиксированных формул, весов, порогов и обязательных
  списков метрик в коде нет; константы допустимы только как определения стандартов
  (BS.1770, true peak, частота дискретизации).
- **Поиск вместо угадывания**: несколько кандидатов на шаг (число — бюджет проекта, не константа), рендер секции, замер, выбор лучшего.
- **Гейты**: моно, клиппинг/true peak, динамика не ниже 10-го процентиля корпуса, фаза,
  консистентность между секциями.
- **Отложенный референс**: цели по N−1, проверка на N-м.
- **Остановка**: все z ≤ 1.5, гейты чисты, три шага без прироста, отложенный не выбивается.

## 7. Модели

- Только «уши-подписант»: одна функция `listen`, движок параметром.
- Работают по стему, по одному клипу, отдают текст и измеренные факты рядом.
- Не принимают решений, не сравнивают A/B (позиционный бин), не читают числа из промпта.
- 16 кГц: верх, тарелки, сибилянты — только по замерам и картинке.

## 8. Универсальность

- Таксономия ролей общая: барабаны (кик/снейр/хэты/тарелки), бас, гитары (ритм/лид/гармония),
  клавиши, вокал (скрим/чистый/бэк), «остальное». Жанр не зашит.
- Цели, допуски, веса — из корпуса и настроек; ни одного «для блэка делай так».
- Метод переносится на любой инструментальный проект: меняется корпус, а не код.

## 9. Критерий готовности

По запросу «вот корпус референсов» система: строит цели → показывает карту трека и отклонения →
ведёт цикл правок с проверкой каждой → останавливается по критериям → отдаёт мастер и стемы,
отчёт с дельтами и журналом. Все утверждения подкреплены замерами; ничего не пропущено молча.

## 10. Что остаётся человеку

Выбор корпуса, веса приоритетов и финальное «звучит как надо». Всё остальное — измеримо и
проверяемо.
