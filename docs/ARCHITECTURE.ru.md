# Архитектура и поток данных

REAPER Workbench разделяет интеграцию с хостом, операции над проектом, анализ сигнала и обнаружение возможностей для модели. MCP-сервер — необязательный интерфейс Python-библиотеки, а не механизм доступа к REAPER.

## Путь запроса

~~~mermaid
flowchart LR
  Client[MCP-клиент или Python-программа] -->|stdio или Python API| Core[Python-библиотека]
  Core --> BridgeClient[Клиент ReaperBridge]
  BridgeClient -->|локальные файлы запросов и ответов| Lua[Resident Lua ReaScript]
  Lua -->|документированный ReaScript API и Actions| Reaper[REAPER]
  Reaper -->|контекст проекта, рендеры| Lua
  Lua -->|структурированный ответ| BridgeClient
  BridgeClient --> Core
  Core --> Analysis[Анализ и сравнение аудио]
  Analysis -->|отчёт, аудиоресурсы с lease| Client
~~~

Resident-скрипт работает во встроенном Lua runtime REAPER. Процесс Python обменивается с ним файлами в `%LOCALAPPDATA%` текущего пользователя Windows. Bridge не открывает сетевой порт, не внедряется в процесс REAPER и не читает его закрытую память. Объекты хоста остаются внутри REAPER; Python передаёт ID проекта, GUID, ревизии и типизированные значения вместо сырых указателей.

## Идентичность и контекст проекта

Каждый запрос связан с сессией bridge и идентификатором проекта. ID проекта формируется из пути проекта и GUID мастер-дорожки, поскольку ReaScript не предоставляет отдельный getter GUID проекта. Снимок содержит монотонный счётчик изменений и стабильные GUID объектов. В зависимости от запрошенного уровня детализации контекст может включать:

- дорожки и мастер, имена, индексы текущего снимка, фейдер/панораму/mute/solo;
- структуру папок, sends, receives, маршрутизацию к родителю и мастеру, конфигурацию каналов;
- items, takes, исходные медиафайлы, позиции, длительности, offsets, play rate, fades и активный take;
- порядок FX и, по запросу, значения параметров;
- карту темпа и размера, transport, маркеры/регионы, envelopes и, по запросу, MIDI-ноты.

Индексы — подсказки только в рамках свежего снимка, а не постоянные ID. Правка использует GUID, чтобы снова найти объект в REAPER, и ожидаемую ревизию, чтобы отклонить устаревший контекст. После рендера, `save_as`, переключения проекта или правки, меняющей счётчик состояния, нужен новый снимок.

## Обнаружение возможностей

Встроенный каталог API строится по официальному справочнику Cockos ReaScript. Сейчас это снимок документации v7.85 с 732 сигнатурами функций. Это число описывает каталог, а не API любой установленной версии REAPER и не количество функций, проверенных вживую. Где возможно, вызов проверяется на наличие в текущем runtime.

Для каждой функции API не создаётся отдельный MCP-tool. Двенадцать MCP-инструментов охватывают health сессии, контекст проекта, обзор каталога, структурный поиск API, общий анализ, карты правок, свидетельства по миксу, ревизионные транзакции, общий вызов API, Actions, явное сохранение и освобождение артефактов. Пять шаблонов ресурсов дают документацию доменов API и функций, контекст проекта с ревизией, отчёты анализа и аудио с ограниченным сроком доступа. Точные схемы вызовов определяются актуальным `tools/list`.

Типизированные edit-планы охватывают операции, для которых определены предусловия, снимок исходного состояния, применение и поведение undo. Общие ReaScript-вызовы и Actions остаются доступны для более широкого управления, однако отдельный вызов автоматически не становится транзакцией и не гарантирует отмену библиотекой.

## Правки и переходы состояния

Для типизированной правки библиотека выполняет следующие шаги:

1. Прочитать идентичность проекта, ревизию и целевые объекты.
2. Проверить операцию и построить preview для этой ревизии.
3. Отклонить план, если проект или ревизия больше не совпадают.
4. Применить пакет внутри undo block REAPER.
5. Перечитать затронутые объекты и сравнить итог с планом.
6. Вернуть новую ревизию; undo разрешается только для точной ревизии, созданной этой транзакцией.

Это ограниченная граница безопасности, а не песочница. Общий API-вызов или Action может менять проект, настройки, файлы, transport, плагины или внешние устройства за пределами typed edit layer. Для таких вызовов нужны отдельные проверки и чтение результата.

## Съём и измерение аудио

Анализ проекта использует штатный offline render REAPER, чтобы получить отдельные выходы источников и отдельный master за выбранный временной диапазон. Каждый источник связывается с проектом и ревизией съёма, GUID, диапазоном рендера, частотой дискретизации и доступным контекстом микшера. При захвате временно используются параметры рендера и выбор целей, затем настройки восстанавливаются; REAPER всё равно может увеличить внутренний счётчик изменений. Клиент использует возвращённую post-capture ревизию и не должен перезагружать проект или сбрасывать счётчик.

Пакет анализа объединяет измерения по источникам, временные профили, свидетельства событий/транзиентов, BPM и размер из карты проекта, а также необязательные сравнения с референсом или между источниками. Отчёт отмечает недоступные данные и покрытие, а не подставляет нули без пояснений. Библиотека не выбирает за пользователя целевую громкость, жанровое правило или лимит мастеринга.

`GetAudioAccessorSamples` — отдельная точка съёма исходного сигнала до FX. Он не эквивалентен обработанному рендеру дорожки. Точка сигнала входит в модель данных и должна сопровождать каждый отчёт и аудиоресурс.

WAV для рендера хранятся вне `.RPP` в отдельной папке задания. Manifest ограничивает очистку файлами, созданными библиотекой. Записи анализа и аудиоресурсы MCP имеют ограниченный срок действия; `reaper_release` удаляет файлы завершённого задания. MCP-клиент может передавать аудио своему провайдеру модели; поведение провайдера контролируется настройками клиента, а не этой библиотекой.

## Почему список MCP компактен

Поверхность REAPER широка, но модель получает сгруппированный доступ через контекст проекта, обнаружение возможностей, анализ, поддерживаемые правки и явные низкоуровневые вызовы. Перед вызовом функции модель может изучить домен API или найти операцию по структурированным полям «объект/операция/уточнения». Это упрощает обнаружение, сохраняя доступ к широкому каталогу ReaScript; фиксированный музыкальный pipeline не задаётся.

## Текущие ограничения

- Пока поддерживается только Windows; путь runtime использует `LOCALAPPDATA`.
- Каталог API шире набора функций, проверенных вживую и обёрнутых typed-транзакциями.
- Общие API-вызовы и Actions не покрываются гарантиями отката typed edit layer.
- Съём аудио выполняется offline render, а не realtime-потоком; счётчик изменений проекта может вырасти после восстановления временных настроек.
- Эквивалентность точки съёма нужно проверять для версии REAPER, способа рендера, маршрутизации, FX и конкретного источника. До-FX данные AudioAccessor заведомо отличаются.
- Это экспериментальная разработка без обещания стабильной совместимости.
