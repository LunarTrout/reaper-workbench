# Установка и подключение

Это руководство устанавливает Python-клиент и загружает resident Lua bridge в REAPER. Затем MCP-клиент подключается к Python-серверу по stdio. Не нужны REAPER-плагин, настройка distant API, открытый сетевой порт или включённый Python внутри REAPER.

## Требования

- Windows. Сейчас это единственная документированная и проверенная платформа для bridge.
- REAPER с включённым ReaScript. Живые проверки выполнялись на REAPER 7.84; доступность отдельных функций зависит от версии.
- Python 3.13 или новее для внешней библиотеки и MCP-сервера.
- MCP-клиент с поддержкой запуска локального stdio-сервера, если нужен доступ через MCP.

REAPER содержит встроенный Lua runtime для ReaScript. Отдельный процесс Python общается с resident-скриптом через локальную файловую очередь; Python не нужно включать в настройках REAPER, а его разрядность не должна совпадать с разрядностью REAPER.

## 1. Получить исходники и установить Python-зависимости

Склонируй репозиторий, затем открой PowerShell в его папке:

~~~powershell
git clone https://github.com/LunarTrout/reaper-workbench.git
Set-Location reaper-workbench
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[mcp]"
~~~

Для разработки и тестов также установи дополнительную группу зависимостей:

~~~powershell
python -m pip install -e ".[dev,mcp]"
python -m pytest
~~~

Дополнение `mcp` устанавливает необязательный MCP SDK. Базовую Python-библиотеку можно использовать без MCP-сервера.

## 2. Установить Lua bridge

Два Lua-файла должны находиться рядом: bridge находит JSON-помощник относительно собственного пути.

1. В REAPER выбери **Options → Show REAPER resource path in Explorer**. Откроется активный каталог ресурсов, в том числе для portable-установки.
2. Открой его папку `Scripts` и создай внутри подпапку, например `REAPER-Workbench`.
3. Скопируй в неё `scripts/reaper_bridge.lua` и `scripts/lua_json.lua` из репозитория.

Не переименовывай один файл отдельно, не изменив путь загрузки помощника в bridge. Runtime bridge и временные аудиофайлы анализа хранятся отдельно от файла проекта.

## 3. Запустить resident bridge в REAPER

1. Открой REAPER и проект/экземпляр, которым должна управлять библиотека.
2. Открой Action List (обычно клавиша `?`).
3. Выбери **ReaScript: Load...**, укажи `reaper_bridge.lua` и добавь скрипт в список действий.
4. Запусти добавленное действие. Скрипт останется активным как deferred ReaScript и будет обслуживать локальные запросы.

Bridge использует Lua runtime REAPER и документированный ReaScript API. Каталог discovery и файлы запросов/ответов создаются здесь:

~~~text
%LOCALAPPDATA%\REAPER-Audio-Library\runtime\
~~~

У runtime-каталога сохранено прежнее внутреннее имя для совместимости. В нём находятся файлы обмена с bridge и краткоживущие артефакты анализа, а не проекты и не накапливаемый архив стемов.

MCP-сервер не выбирает проект по имени файла. Сначала вызови `reaper_session(action="health")` и `reaper_project`. Если работают несколько экземпляров REAPER с bridge, передавай возвращённый bridge session ID в следующих вызовах, чтобы запросы относились к нужному экземпляру.

### Каталог контрольных сохранений

`reaper_checkpoint_save` сохраняет новый файл `.RPP` и отказывается перезаписывать
существующий. По умолчанию разрешён каталог
`%USERPROFILE%\Documents\REAPER Workbench\versions`; создай его перед первым
сохранением. Чтобы хранить версии рядом с конкретным проектом, задай
`REAPER_CHECKPOINT_ROOT` в окружении процесса MCP-сервера и укажи существующий
отдельный каталог. В конфигурации MCP-клиента переменную можно передать в поле
`env` сервера. Запрошенный путь сохранения должен находиться внутри разрешённого
каталога.

Остановить bridge можно из Action List, остановив работающий deferred script. В [официальном руководстве Cockos по ReaScript](https://www.reaper.fm/sdk/reascript/reascript.php) описано, что deferred-скрипты продолжают работать в фоне, пока их не остановят через список запущенных скриптов.

## 4. Настроить MCP-клиент

Сервер использует стандартные ввод и вывод. Добавь в конфигурацию MCP-клиента запись такого вида; путь к Python укажи абсолютный и ведущий в виртуальное окружение:

~~~json
{
  "mcpServers": {
    "reaper-workbench": {
      "command": "C:\\path\\to\\reaper-workbench\\.venv\\Scripts\\python.exe",
      "args": ["-m", "reaper_audio.mcp_server"]
    }
  }
}
~~~

Расположение файла и формат настроек зависят от MCP-клиента. Команда должна запускать Python с аргументами `-m reaper_audio.mcp_server`. Не запускай её через оболочку, которая печатает приветствие или другой текст в stdout: stdout является каналом MCP.

После подключения работай в таком порядке:

1. Вызови `reaper_session` с `action="health"`, чтобы проверить bridge.
2. Вызови `reaper_project`, чтобы получить идентификатор и ревизию проекта, дорожки, мастер, маршруты и темп.
3. Перед низкоуровневым вызовом найди операцию через `reaper_capabilities` или `reaper_api_search`.
4. Поддерживаемую правку сначала подготовь как план с ревизией, затем примени и перечитай затронутые объекты. Откат выполняй только если возвращённая ревизия по-прежнему указывает на эту транзакцию как на последнюю.

Контракт инструментов и работу с контекстом описывает [MCP-README-LLM.ru.md](MCP-README-LLM.ru.md).

## Аудио и файлы проекта

Для анализа проекта библиотека использует штатный offline render REAPER: отдельно получает выходы источников и отдельный мастер. Временные WAV хранятся вне `.RPP` в папке задания; `reaper_release` или очистка просроченных заданий удаляет их. Эти WAV не вставляются как дорожки в плейлист и не должны накапливаться как версии проекта.

AudioAccessor — отдельная точка съёма до FX; она не заменяет обработанный рендер дорожки. Во время захвата библиотека временно меняет параметры рендера и выделение, если это необходимо, затем восстанавливает их и возвращает новую ревизию проекта. После захвата перечитай контекст; не считай, что счётчик изменений остался прежним.

Дальнейшая передача аудиоресурсов зависит от MCP-клиента. Клиент может отправлять аудио внешнему провайдеру модели в соответствии со своими настройками; этот репозиторий не управляет действиями на стороне провайдера.

## Устранение неполадок

| Симптом | Что проверить |
|---|---|
| `bridge_unavailable` | REAPER открыт, а deferred-скрипт `reaper_bridge.lua` работает именно в целевом экземпляре. |
| Lua не находит `lua_json.lua` | Оба файла находятся в одной папке; REAPER загрузил правильную копию `reaper_bridge.lua`. |
| Ошибка `LOCALAPPDATA` | Запусти REAPER в обычной пользовательской сессии Windows со стандартными переменными окружения. |
| API-функция недоступна | Каталог описывает сигнатуры, а runtime-доступность определяется версией REAPER. Найди функцию и проверь результат вызова. |
| `stale_context` | Перечитай проект, изучи изменения и создай новый план. Не повторяй старый план с новой ревизией. |
