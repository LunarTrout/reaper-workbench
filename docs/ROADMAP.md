### 1.2 Цикл «корпус → EQ → рендер → замер»

`work/eq_cycle.py` (3 × ReaEQ, 6 полос, калибровка по значениям самого плагина):

```
before:  -13.60 LUFS, distance 10.295
accepted (25 Hz, -6.9 dB) -> 8.941
accepted (32 Hz, -6.5 dB) -> 8.364
accepted (125 Hz, -5.3 dB) -> 7.950
rejected (160 Hz, -4.5 dB) -> 9.334
rejected (1600 Hz, +3.9 dB) -> 9.540
rejected (6300 Hz, +3.8 dB) -> 9.065
final:   -12.74 LUFS, distance 7.950  (ratio 0.772)
```

Что это доказывает:

1. **Правки делаются через REAPER, а не в файле** — плагин, параметры,
   рендер мастера, замер результата.
2. **Перебор работает и отсекает вредное**: три правки приняты, три
   отклонены с откатом, потому что модель предпочла состояние без них.
   Никаких «2–3 дБ за шаг» в коде нет — величина приходит из дельты, решение
   из сравнения отрендеренного результата.
3. **Компенсация громкости** возвращает файл к исходному LUFS (−12.74 против
   −13.60 до правок); без неё EQ уводил громкость на 2.7 дБ вниз.
4. **Ограничение**: две peaking-полосы на инстанс ReaEQ. Шелфы и фильтры
   исключены из плана правок — попытка «сдвинуть» high shelf на 160 Гц уронила
   громкость на 5.5 дБ и была отброшена как явный дефект.

### 1.3 Бенчмарк: отличает ли оценка производственную правку от личности трека

Протокол: leave-one-source-out, 38 фрагментов из 5 источников (альбом — один
источник), окна 15 с, 42 признака, 10 контролируемых деградаций.
`work/corpus_benchmark_38.json`.

| Деградация | Оригинал ближе | Отношение | Было на 6 файлах |
|---|---|---|---|
| mono | **1.00** | 38.8 | 1.00 |
| air cut (LP 8k) | **1.00** | 2.64 | 1.00 |
| bright (+3 дБ/окт) | **1.00** | 2.05 | 1.00 |
| narrow (side ×0.4) | **1.00** | 1.77 | 1.00 |
| dark (−3 дБ/окт) | **1.00** | 1.72 | 0.97 |
| mud (+5 дБ @250) | 0.88 | 1.08 | 0.69 |
| presence cut (−5 дБ @3k) | 0.79 | 1.03 | 0.75 |
| compressed (6:1) | 0.64 | 1.01 | 0.58 |
| clipped (0.5 FS) | 0.36 | 0.99 | 0.42 |
| gain (−6 дБ) | 0.54 (шум вокруг нуля) | **1.00** | 1.00 |

Выводы:

- **Громкость инвариантна** (ratio 1.00) — оценка не путает уровень с балансом.
- **Корпус из 5 источников вместо 6 отдельных файлов улучшил тонкие оси:**
  mud 0.69 → 0.88, dark 0.97 → 1.00, presence 0.75 → 0.79.
- **Компрессия и клиппинг дистанцией не ловятся.** Клиппинг — гейт (§1.4).
  Для компрессии добавлены короткие кресты (100 мс, p50/p95): 0.58 → 0.64,
  всё ещё слабо; следующий шаг — крест по полосам и маскировка, а не ещё одна
  константа.
- Корпус по-прежнему мал и неоднороден: 5 источников, из них 2 Windir и 2
  Grima, ни одного tech death. Это ограничение данных, а не модели.

### 1.4 Гейты дефектов

`corpus/gates.py` — отдельный слой, не смешанный с тональной оценкой:

| Гейт | Что меряет | Тест |
|---|---|---|
| clipping | прогоны на FS + плоские вершины у максимума | 6 тестов |
| dc_offset | постоянная составляющая | |
| dropouts | прогоны тишины внутри материала | |
| level_jumps | шаг RMS между окнами 1 с | |

Политика (пороги) приходит из настроек проекта; в коде порогов нет.
Клиппинг ловится и тогда, когда сигнал не доходит до 0 dBFS (плоские
вершины), — именно этого не умела дистанция в §1.3.

Проверка на нашем мастере (`work/assess_ours_policy.json`): найдено 9
клиппинг-ранов (до 26 сэмплов) и true peak +0.09 dBTP — реальный дефект
рендера. Гейт `level_jump` при этом сработал на 16.5 дБ между окнами 1 с:
это переход от тихого вступления к группе, а не дефект. Значит, порог
`level_jump` нельзя задавать на весь трек — только внутри секции, иначе он
ловит музыкальную динамику. Это записано как требование к политике, а не
исправлено константой.

## 3. Найденные и закрытые узкие места

1. **`fx.insert` не работал вообще.** В мосте `TrackFX_AddByName` вызывался с
   `instantiate=false`. В этом REAPER семантика обратная: `false` вставляет,
   `true` только ищет. Проверено прямыми вызовами: с `false` FX появляется,
   с `true` счётчик не растёт. Исправлено, добавлен повтор для холодного
   кэша VST.
2. **`position` у `fx.insert` ненадёжен** — вставка с `position=0` не
   происходила. В цикле используется вставка в конец; сортировка — отдельная
   задача.
3. **Ошибки транзакции теряли причину**: в отчёт попадало `table: 0x...`.
   Теперь в деталях исходное сообщение.
4. **Калибровка параметров ломалась на `-inf`** (гейн 0 → «-inf»): теперь
   нефинитные точки отбрасываются, кривая кусочно-линейная по конечным точкам.
5. **Шелфы нельзя двигать по частоте**: high shelf на 160 Гц — не «правка», а
   другой фильтр; из плана исключены, остаются peaking-полосы.
6. **Накопление состояния**: повторный прогон применял правки поверх старых.
   `apply_moves(flatten=True)` возвращает все полосы к 0 дБ перед правкой.

## 4. Что закрывать дальше, по приоритету

### P0 — без этого «студийного» результата не будет

1. **Корпус 20–30 однородных референсов** (тяжёлые/сложные жанры), с
   разделением: микс или мастер, год, поджанр, полные треки против альбомов.
   Сделано: альбомы разрезаны по тишине на 38 фрагментов
   (`work/split_corpus.py`, `work/corpus_tracks`), LOTO теперь по источнику, а
   не по файлу. Осталось: другие исполнители (сейчас 5 источников, из них 2 —
   Windir и 2 — Grima) и tech death.
2. **Гейты как отдельный слой**: клиппинг (раны на FS), true peak, mono loss,
   DC, обрывы, скачки уровня между секциями. Они не входят в расстояние и
   проверяются до/после правки. Бенчмарк показал, почему: клиппинг дистанцией
   не ловится.
3. **Стадии**: микс и мастер сравнивать раздельно; мастер-цели (LUFS, LRA,
   PLR, TP) — отдельный набор, не подмешивать в тональную оценку.
4. **Роли и секции**: карта роль→дорожка и границы секций из проекта, а не из
   жанровых догадок. Цели по (роль, секция) с числом наблюдений и `reliable`.

### P1 — точность решений

5. **Больше полос**: несколько EQ-инстансов или плагин с большим числом
   параметров; альтернатива — shelves с политикой «не двигать угол».
6. **Поиск величины правки**: сейчас кандидаты берутся из дельты целиком.
   Следующий шаг — сетка долей (0.25/0.5/1.0) и выбор по замеру; доли — бюджет
   поиска, не константа метода.
7. **Компрессия/динамика**: crest по коротким окнам (100 мс) и распределение,
   а не одно значение на окно 10 с — иначе 6:1 не видно (0.58 в бенчмарке).
8. **Маскировка**: SMR по ERB между ролями — единственный конструкт с
   опубликованной корреляцией с восприятием (ρ≈0.84, малая выборка).

### P2 — масштаб

9. **Стемы референсов** с калибровкой протечки. Измерено на этой V100
   (`docs/stem-separation.md`): BS-RoFormer SW 6-stem — 14.8× realtime, пик
   2.65 ГБ, даёт bass/drums/other/vocals/guitar/piano; MVSep Mega-53 — 4.96×,
   7.56 ГБ, единственный открытый источник accordion / electric-guitar /
   back-vocal / lead-vocal. Лицензии: у SW веса `unknown`, у DrumSep лицензии
   нет; чистый стек — PolarFormer (MIT) + SCNet XL IHF + inagoy/drumsep.
   Отдельных «4 гитар» и «скрим против чистого» не даёт ни одна открытая
   модель — цели по этим осям не строить. Сумма стемов должна возвращать микс;
   это отдельная проверка перед любыми целями по ролям.
10. **Выравнивание дублей** по транзиентам с проверкой корреляции/фазы и
    журналом смещений (в библиотеке есть `daw/alignment.py`, но матчер
    транзиентов ещё не написан).
11. **Автоматизация панорамы** и пространство — после того как тон и динамика
    перестанут быть шумом.

REAPER запускается как обычно; `__startup.lua` поднимает мост. MCP-сервер для
этих прогонов не нужен — всё идёт через `ReaperBridge` и `ProjectSession`.

## 6. Честная граница

Сегодняшний результат — «грамотный ассистент»: он видит дельты, делает
обратимые правки через DAW, проверяет результат замером и откатывает вредное.
Он **не** гарантирует студийное качество: валидированной метрики качества
микса не существует, а корпус в 6 треков не позволяет принимать тонкие
решения. Следующий качественный шаг — не новый алгоритм, а корпус, гейты,
стадии и роли (P0), и только потом — более тонкие признаки (P1).
