# Безопасность и гарантии состояния проекта

Документ фиксирует, какие риски библиотека сейчас ограничивает, а где вызывающая сторона должна выполнить дополнительные проверки. Он не гарантирует безопасность автоматизации любой функции REAPER или любого Action.

## Граница доверия

- REAPER остаётся хостом проектных объектов и обработки аудио. Lua bridge работает внутри REAPER и вызывает ReaScript API или Actions.
- Python-клиент и MCP-сервер обмениваются с bridge файлами в `%LOCALAPPDATA%` текущего пользователя Windows. Сетевой порт этот транспорт не открывает.
- Любой локальный процесс с правом записи в runtime-папку может иметь возможность передать команды bridge. Защищай профиль Windows и не переноси эту папку в общую или сетевую директорию.
- MCP-клиент может получить контекст проекта и аудио с lease, а также отправить команды правки. Пользователь/оператор сам решает, какому провайдеру модели разрешено передавать проект или звук.

## Привязка к контексту

Правки должны быть привязаны ко всем перечисленным параметрам:

- bridge session ID — нужный процесс REAPER;
- project ID — нужный открытый проект;
- ожидаемая ревизия — проверка, что модель читала актуальное состояние;
- GUID объектов — поиск дорожек, items, FX и других объектов внутри REAPER.

Индексы дорожек действуют только в пределах одного снимка и не должны использоваться как постоянные ID. Если ревизия поменялась между preview и apply, отбрось план, перечитай контекст и построй новый.

## Типизированные транзакции правок

Для поддерживаемых операций используй последовательность preview/apply/undo инструмента `reaper_edit`. Preview не меняет проект и возвращает план, привязанный к текущей ревизии. Apply отклоняет устаревшие планы и возвращает новую ревизию. Перечитай все изменённые объекты. Undo разрешается только с точной ревизией, возвращённой целевым планом, и пока его не перекрыла новая правка.

Набор типизированных транзакций уже, чем весь ReaScript API. Общие `reaper_api_call` и `reaper_action` позволяют вызывать операции за пределами набора. Они могут сохранять/закрывать проекты, менять preferences, влиять на устройства или плагины, создавать/удалять файлы или менять глобальное состояние. Их эффекты автоматически не ограничиваются транзакционным слоем. Перед вызовом изучи сигнатуру и побочные эффекты; после вызова проверь проект и внешнее состояние.

## Сохранение, рендер и медиа

- Сохранение выполняется явно. `save_as` проверяет целевой путь и не перезаписывает существующий файл без явного флага перезаписи.
- Рендер и съём аудио создают артефакты; удаление артефактов не делает сам рендер обратимой операцией.
- Файлы анализа хранятся вне `.RPP` в папке задания. Очистка ограничена путями, принадлежащими библиотеке и записанными в manifest задания. Не удаляй вручную путь из ошибки очистки, пока не проверены его manifest и владельцы.
- При съёме анализа временно меняются параметры рендера и набор целевых дорожек. Bridge восстанавливает их и возвращает новую ревизию. Внутренний счётчик изменений может увеличиться; используй возвращённую ревизию, не сбрасывай счётчик и не перезагружай проект.
- Анализ проекта использует offline render и отдельный master. `GetAudioAccessorSamples` возвращает сигнал до FX и не эквивалентен обработанному рендеру дорожки.
- Полный менеджер исходной и финальной версий проекта ещё не реализован. Перед важными правками сохраняй отдельную копию.

## Приватность аудио и провайдера модели

Bridge и библиотека анализа обрабатывают звук локально. При этом MCP-клиент может передать аудиоресурсы и контекст проекта удалённому провайдеру модели. Перед включением доступа к аудио проверь политику приватности и хранения данных этого клиента. Библиотека не может управлять тем, что провайдер сохраняет после получения данных.

Временное аудио выдаётся на ограниченный срок и очищается после `release` или при очистке просроченных заданий. После аварийного завершения папка задания может остаться до следующей очистки. Политика рассчитана на то, чтобы стемы анализа не копились; при ошибке проверь результат очистки.

## Практика работы

1. Для первого запуска и неизвестных операций используй дубликат проекта.
2. Перед правками подтверди ID bridge-сессии и проекта.
3. Прочитай актуальную ревизию и достаточный контекст для выбора цели.
4. Для поддерживаемых изменений применяй typed preview/apply; общий API и Actions используй после проверки их смысла.
5. Перечитай изменения и проверь undo-state перед восстановлением.
6. Сохраняй только по запросу и в явно выбранный путь.

Код пока экспериментальный. Эти механизмы ограничивают отдельные классы ошибок, но не гарантируют правильные музыкальные решения модели и не обещают откат любой операции.
